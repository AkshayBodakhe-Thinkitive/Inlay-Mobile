At a glance

Three layers. Each one may use the one below it, never the one above.

src/navigation — who goes whereRoot → Auth / App stacks, tab bar, typed route params
↓ uses
src/features/<name> — one folder per product areascreens, components, hooks, services, types, mock, tests
↓ uses
src/shared — used by 2+ featuresapi client, components, config, i18n, store, hooks, utils

Inside one feature

Screen→Hook (React Query)→Service→apiClient (axios)→Backend

Screens never import axios. Services are the only place that call the API.

shared/ never imports from features/ — two known exceptions exist (shared/api/client.ts and shared/store/index.ts import auth/notification slices); don't copy them.

3Feature anatomy & the dependency rule

Every feature has the same shape; create only the folders you need.

Flowscreen → hook → service → apiClient. Screens never import axios.
Dependency directionshared/ never imports from features/. Features may import shared/ freely, and another feature's hook/type only when truly needed.
Redux vs React QueryServer data (lists, details, paging) → React Query. Only session, toasts, error popup, connectivity and live counters → Redux.
Types from the schemaCopy from the Swagger schema, never guess. Each service/type file notes what it was checked against.
StringsNo hardcoded UI text. Add the key to both en.json and hi.json.
Safe areasFull-screen stack screens: SafeAreaView edges={['top','bottom']}. Tab screens leave the bottom to the tab bar.
Android is edge-to-edge: a missing bottom edge hides the last button behind the system nav bar.

  • Fonts load with expo-font first (Inter Regular / Medium / SemiBold / Bold).
  • Splash stays up until the animation and auth rehydration (token + profile from SecureStore) are both done.
  • Add each new screen to the stack and to navigation/types.ts.
  • Deep links: the linking config in App.tsx (custom scheme + https domain); its screens must mirror the navigator nesting.
  • Keep a docs/project-arch/navigation-tree.md mapping each screen to its folder and entry points.

5API layer — shared/api/client.ts

One axios instance, baseURL = <active env>/api/, 10 s timeout. Behaviour to reproduce:

StepBehaviour
RequestAttach Authorization: Bearer <token> from SecureStore. Dev builds log method + URL (auth bodies redacted).
Network failure / timeoutRetry safe requests with backoff (retryPolicy); offline → queue idempotent requests for replay (retryQueue); online timeout → toast. Callers that own offline handling pass skipOfflineHandling.
401Refresh the token once, replay the request, queue other requests meanwhile. Failed refresh → toast + clear storage + logout. A 401 after the retry also logs out.
403 account restrictedToast the server's message, clear storage, log out.
Other errorsReject with a translated ApiError(message, code, status, errors). Branch on code, never on message text. The global error popup is intentionally disabled.
Env switchenvStore holds the live base URL; the instance re-points itself without being rebuilt.

Environments

environments.ts lists dev / qa / uat / production, each URL from EXPO_PUBLIC_API_BASE_URL_*. A picker (EnvironmentPicker, opened by a hidden tap on the login logo) switches at runtime and saves the choice.

Mock mode

EXPO_PUBLIC_USE_MOCK=true: services return fixtures from mock/, auth uses placeholder tokens, and mockMode.ts makes the client refuse any real network call so nothing logs you out. Chat and notification sockets stay off in this mode.

6Config, env & flags

  • All build-time values are EXPO_PUBLIC_* in .env (gitignored); .env.example documents each.
  • After changing .env, restart Metro: npx expo start -c.
  • Feature flags are plain booleans exported from shared/config/env.ts (USE_MOCK, ENABLE_MESSAGES, ENABLE_TRENDS, …). A flagged-off feature keeps its tab/entry visible and shows a "coming soon" state instead of vanishing.
✔ Works
process.env.EXPO_PUBLIC_API_BASE_URL_DEV
✘ Undefined at runtime
process.env[`EXPO_PUBLIC_${name}`]

Expo replaces process.env.EXPO_PUBLIC_X by text substitution at build time, so write each variable out in full.

7Auth & storage

Phone / email→OTP→Consent screen(s)→Role / profile chooser
  • StorageService (SecureStore) holds token, refresh token, profile, FCM token and active profile ids; clearAll() is the single sign-out wipe. Never put secrets in AsyncStorage.
  • authSlice holds isAuthenticated, user, active profile, isSwitchingProfile; logout is dispatched from the API client.
  • Password reset arrives by deep link.
  • Push permission is requested at startup; the device token is registered with the backend at login.

9Testing

  • Tests sit in a __tests__ folder next to what they test, named <File>.test.ts(x).
  • jest.setup.js globally stubs native modules that break at import (AsyncStorage, expo-crypto, react-native-blob-util, react-native-razorpay). Add a stub whenever a native module throws under Jest.
  • src/__mocks__/ holds stubs for heavy components (ButtonStub, CheckBoxStub) wired via moduleNameMapper; Firebase modules are mapped the same way.
  • Typical suite: mock the service, render the screen, assert on keys (i18n is mocked to return the key).
Rule: every changed or new source file gets a test in the same PR.

11Native & build config

  • app.json: portrait only; iPad supported with full-screen requirement; bundle id / package name; Firebase plist + json; associated domains; custom scheme for deep links.
  • Config plugins in plugins/ patch the generated native projects. They run on every expo prebuild, so native fixes belong there, not in ios/ or android/.
  • eas.json: development, preview, qa, uat, production (+ submit). Local Android builds via npm run build:android:qa|uat.
  • Metro: SVG transformer + NativeWind wrapper in metro.config.js.

13Pitfalls this codebase already hit

EXPO_PUBLIC_* computed lookups silently return undefined — write each variable in full.
Android edge-to-edge hides bottom-aligned buttons unless the screen's SafeAreaView includes the bottom edge.
Native modules that create an event emitter at import time crash Jest — stub them in jest.setup.js.
Mock login with real sockets/API calls logs the user out via the 401 handler — gate sockets and unmocked calls on USE_MOCK.
Push tap that cold-starts the app needs both the expo and the Firebase initial-notification checks; verify on a real device.
Missing i18n keys render as the raw key (e.g. symptoms.picker.other) — add to both locale files and check after any rename.
